# 花友玩法与盆栽定制提案

## 花友卡牌：三回合花展

两位花友各拿三张不同物种的卡。每回合先公开天气，再各自扣下一张未用的卡，同时翻开。三回合结束，赢得回合多的一方获胜，胜场相同则握手言和。一局结束后所有卡仍归各自所有。可以用下面六张纸牌先试规则。

| 物种卡 | 行动 | 加分天气 |
| --- | --- | --- |
| 银杏 | 展叶 | 晴 |
| 薄荷 | 扎根 | 雨 |
| 雏菊 | 开花 | 晴 |
| 鸡爪槭 | 展叶 | 雪 |
| 拟石莲花 | 扎根 | 晴 |
| 蒲公英 | 开花 | 雨 |

每张卡有 2 点基础分。行动按「展叶胜扎根、扎根胜开花、开花胜展叶」循环克制，克制加 2，天气吻合加 1。比分高的卡赢本回合，同分双方都得 0 胜场。每回合独立抽取晴、雨、雪之一，各占三分之一。例如晴天银杏对薄荷，银杏得到 5 分，薄荷得到 2 分，银杏赢一回合。卡面的行动和天气是游戏数值；另设观察栏展示真实的叶形、花序等知识。双方花园的天气开关只影响各自布景。

**收藏如何解锁。** 新账号可借银杏、薄荷、雏菊三张体验卡凑齐一副。确认识别物种并种下实拍植物时永久解锁对应卡，领取花友的分株也可解锁。图鉴试种只借用体验卡。重复采集同一物种可以换自己的展示照片，战力固定；移除原株不回收已解锁的卡。首版只给策划目录中的物种配卡，中文名、学名带命名人或旧学名都通过别名映射到同一物种编号。目录外仍可正常种植。

**线上接法。** 当前好友接口已有双方同意的关系，礼物接口也能核验来源。对局沿用植迹会话，由服务端确认双方仍是好友。新增独立的「用户已解锁物种」记录，用户与物种组成唯一键。实拍解锁依据服务端签发的识别候选凭据和已保存的种植结果，分株解锁依据已领取礼物；失败重试用同一来源编号补记。服务端只给对手发送目录卡面、公开出牌和比分，私人观察照片、地点及手记无须进入对局。

邀请被接受后固定双方牌组和规则版本，服务端保存三回合的天气序列，每回合开始只公开当前天气。每方每回合只能锁一张手牌，两人都锁牌后在一次数据库事务中揭牌、记分、推进回合。重复提交同一操作直接返回原结果，换牌或提交过期回合返回冲突。刷新后继续同一局。首版用短轮询即可，24 小时无人完成的回合结束对局并标为过期。解除好友后终止未完成的局。

**试玩门槛。** 已枚举六张卡在三种天气下的 108 组有序单回合对阵，包括同卡相遇。每张卡在每种天气下都有能赢和会输的对手。整局策略还需试玩：让两名新同学仅凭卡面完成一局；若要额外解释克制或结算，就先改卡面。开发联机前用固定牌组和天气种子交换座位重放，分数应镜像一致。联机验收再覆盖双方同时出牌、双击提交、掉线重连、拒绝邀请和非参与者访问。无论结果如何，两人的植物和礼物箱都应与开局前一致。

## 盆栽定制

本次已接入赤陶、青瓷、玄武岩三个预设。进入室内的「布置花园」，选中植物即可切换。以下是进一步开放轮廓、釉色和纹样的扩展方案。

室内植物和陶盆已在 `dist/specimen.js` 分开生成。叶形、花序、照片配色继续由物种模型负责，盆型只控制外壳轮廓、盆沿和土面高度。因此可以先拿同一株薄荷试三种搭配：低矮圆盆配赤陶、直筒盆配青釉、宽口盆配砂白。扩展阶段可提供三种轮廓、三种釉色和素面或环纹，共 18 种组合。

- **编辑流程。** 在室内已种植物的详情里进入「换花盆」，同角度预览新旧效果，确定后保存。给记录添加可选的盆型、釉色、纹样枚举；旧记录默认沿用当前陶盆。移到室外地栽时收起外盆，回到室内恢复原装饰。分株给好友时使用收礼人的默认花盆。
- **造型与摆放。** 根据盆型的实际土面高度定位根部，让植株尺寸和叶形保持稳定。预先测量每个盆型的最大外半径，碰撞取盆体和植株包围半径中的较大值。换宽盆后空间不足，保留原配置并提示先挪开，确认保存前不移动邻近物品。
- **同步与渲染。** 服务端校验三个枚举；模型和精灵缓存键包含盆饰配置。详情缩略图、室内场景、花友参观和照片导出读同一配置。改变釉色只重绘盆身，不重复向 DeepSeek 请求植物模型。
- **验收门槛。** 先用小草、莲座植物和树苗分别试低盆、宽盆，平视与俯视都能看到根部接土，花盆不遮住整株小草。再验换盆碰撞、取消编辑、跨设备重载、好友参观和拍照导出均与预览一致，才扩展到托盘、贴花和室外可移动花盆。

卡牌需要新增对局和解锁状态，适合先用上述六张卡验证是否好玩；盆饰第一步可以只做本地模型预览，检查株形和盆沿比例后再开放账号同步。这两项属于设计提案。
