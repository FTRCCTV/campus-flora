# 校园植物园在中国大陆的部署方案

本项目目前使用 Cloudflare Worker、R2 和 D1。以下是迁移方案，尚未开通服务器、迁移用户数据或从中国农大校园网实测。

## 比赛期间怎么选

| 条件 | 推荐做法 |
| --- | --- |
| 学校能提供已获准使用的域名、HTTPS 和应用服务器 | 优先申请学校子域名，由学校网络中心确认备案主体、接入商和对外开放范围。在比赛前用校园 Wi-Fi 和手机流量各走完一次拍照到入园流程。 |
| 个人团队，临近答辩 | 先在现场验证现有在线版，准备 Release 中的 `campus-flora-offline.html` 演示三维布景。如果必须提供新的公网入口，可先在香港节点试部署同一应用。香港节点无需办理大陆服务器的 ICP 备案，跨境链路仍需实测。离线版可用示例植物布景，实拍识别、账号同步和好友互动需要在线服务。[腾讯云备案资源说明](https://cloud.tencent.com/document/product/243/18908/) |
| 长期对大陆用户开放 | 建议采用腾讯云北京地域轻量应用服务器、持久化数据盘和同域 HTTPS，以一个实例承载网站和 API。个人项目先核对接入商对个人主体和服务内容的要求，学校名义运营则由学校授权办理。大陆公网服务上线前应完成 ICP 备案，已有备案域名换接入商时先核对接入备案手续。购买前确认实例符合备案资格。[腾讯云备案条件](https://cloud.tencent.com/document/product/243/18908/) · [接入备案说明](https://cloud.tencent.com/document/faq/243/43878) |

## 移植与迁移顺序

1. **先移植后端。** 现有 Worker 依赖 R2、D1 绑定，单独上传静态页面只能展示界面。在 Node 服务中复用识别、株形和账号处理逻辑，由反向代理提供同域 `/api` 和 HTTPS。保留原始请求来源、多个 Set-Cookie 响应头以及花园 16 MiB 请求上限。将两项 API 密钥放在服务端环境变量中。
2. **保留并发保护。** 单实例可用持久盘上的 SQLite，按键保存原 R2 对象、内容和版本。首次写入使用唯一键，更新使用带预期版本的条件更新，并维持客户端接受的带引号 32 位十六进制版本格式。两台设备改同一花园时，过期版本应收到 409。用户名占用和调用配额也要保持条件写入。D1 社交数据保留原表、索引及唯一约束，逐表迁移并检查好友关系。多实例部署可用云托管加同地域 MySQL，共享数据和条件更新逻辑，需转换 SQLite 方言及索引。[云托管连接 MySQL](https://cloud.tencent.com/document/product/1243/49231)
3. **先演练数据，再切域名。** 备份并恢复到测试环境，保留账号 ID、密码盐、摘要和修订号。按原用户 ID 导入花园，兼容旧版植物数组和新版含布局的记录，用样本核对照片、摆件、坐标及天气。游客花园位于浏览器旧域名下，换域名前提醒用户在旧站登录并执行「导入本机花园」。新域名需要重新登录，旧域会话在切换时作废。正式切换前短暂停写、同步最后变更并核对数量，再让新站接受写入。保留原库只读备份，若新站已产生写入，回切前先对账补齐。

## 如何确认现场可用

从**候选服务器本身**发一次真实请求。用经同意的植物样照调用 Pl@ntNet 的 `/v2/identify/all`，检查候选学名并记录耗时，再用该学名请求 DeepSeek 的 `/chat/completions`，检查株形参数能否通过项目校验。分别记录超时、鉴权失败和配额不足，日志省略密钥和照片。仅打开服务商首页无法验证这两条链路。[Pl@ntNet 识别接口](https://my.plantnet.org/doc/api/identify) · [DeepSeek 接口](https://api-docs.deepseek.com/zh-cn/)

在中国农大校园 Wi-Fi 和手机流量上分别用手机打开同一 HTTPS 地址，完成注册、拍照识别、栽种、摆放和刷新。随后在第二台设备登录，核对照片、位置和好友关系。记录首屏和识别各自的耗时、成功次数及测试网络，据此决定是否切换正式入口。
