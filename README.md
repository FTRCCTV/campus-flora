# 植迹 · 校园植物手记

植迹是为中国农业大学黑客松制作的校园植物观察 Demo。拍下路边的一株植物，确认它的名字，记下发现地点，就能把这次相遇种进自己的三维植物园。小花草可以摆上窗台，乔木和灌木可以种在窗外。

[下载离线演示版](https://github.com/FTRCCTV/campus-flora/releases/latest) · [打开在线植物园](https://cau-campus-flora-notebook.bubblybox131.chatgpt.site/#garden)

## 第一次体验

**GitHub Pages 部署评估。** `github.io` 可以托管 HTML、CSS、脚本及三维资源，适合做项目展示入口，并链接到完整在线版。若发布纯静态试玩，需要让页面以本地游客模式运行，使用图鉴和同屏对战。仅上传现有网页会让同源的 `/api/*` 请求落到静态站点。拍照识别、账号同步和在线花友对战仍需要后端、数据库和对象存储。完整迁移应另行规划 API 地址、来源校验及登录会话；当前登录使用同源 HttpOnly Cookie。详见 [GitHub Pages 托管说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。

**观察台与花园养护（v0.8.0）。** 首页点选植物，观察台会显示当前代数、阶段和成长进度。拖动可旋转，滚轮或双指可缩放；也可使用方向键、加减键和复位按钮。自有植株可试配盆器材质、盆身贴纸和植株挂饰，点击保存即可同步到花园。花园内展开「养护植株」可浇水、施肥和转盆，成熟后仍可记录照料。

**花友对战。** 默认使用可旋转的立体棋桌。拖动转动视角，轻点落子，也可以切换俯视棋谱。 打开「花友对战」可在一台设备上双人试玩，也可登录在线版后选择已添加的花友。双方进入彼此的房间，一方发起，另一方接受。每轮各行动一次，蝴蝶从 5×5 棋盘的左上角寻找去右下角的最短路径；先到下边为 1P 胜，先到右边为 2P 胜。封死终点后随机游走，完全围住时随机越障一格。破障可重新开放一格实体阻挡。对局数据独立于个人花园。

识别照片后，系统会在后台按规范学名匹配对战体系。赛前为占地、花引、风播、蔓生和破障各选一株植物；缺少对应收藏时，使用该体系的标准植物。同屏双方可以分别配卡，在线对局在邀请和应战时分别锁定阵容。

**物种收集奖励。** 每种植物首次种下并保存后计入物种收集手记。累计 1、2、3、4、5 种，依次解锁黄铜植物铭牌、风送花瓣、青瓷鸟浴盆、流萤微光和日晷观测台。展开「我的植物园」里的手记即可摆放装饰或启用动效，再点「保存布置」。重复种植同一物种只计一次，移除后保留奖励。

**养成与种子。** 保存新植物后，点开植株的「生长手记」进行浇水、转盆、积累成长和收种。按当前阶段的水分、光照和养分目标进行照料，三个数值达标后进入下一阶段，离线期间保持原状。成熟品种永久保存在种子袋，可以再播种，也可以在在线版好友列表里赠送。受赠幼苗会标注赠送者和代数。收集达到 6、8、10、12、15 种分别解锁蝶影花径、花窗流彩、黄铜浑仪、流星天幕和极光星图。

**本地拍照识植。** 从 GitHub Release 下载 `campus-flora-windows-x64.zip`，完整解压后双击「一键启动植迹.cmd」。Windows 10/11 x64 无需安装开发环境或填写密钥。浏览器从本机服务加载页面，识别时向植迹在线服务提交照片，图鉴未收录的物种按学名生成模型。模型渲染和花园保存在本机。使用期间请保持启动窗口开启。

**离线逛花园。** 在 Release 的 **Assets** 中下载 `campus-flora-offline.html`，用浏览器打开，进入「我的植物园」。点选窗台上的雏菊，在种植工作台选择展示大小和区域后确认种植，再拖动盆栽调整位置。再点击窗户进入室外，拖动旋转视角，滚轮或按钮缩放，点「返回室内」回到室内。整个流程可以离线演示。

**在线记录真实植物。** 在「植物探索」中拍照或从相册选图，预览后点「开始识别」。从候选中选定物种，由系统自动匹配株形。用户选择展示大小和种植区域，再填写发现地点。收藏后会立即出现基础株形，后台生成的物种株形就绪后会更新花园。

## 打理花园

花园保留室内花房和室外花园两个空间。旧窗台、工作台和花架会合入室内，旧池畔、步道和草甸会合入室外。原位有冲突时会自动寻找空地。点击「布置花园」可在当前区域内拖动植物和装饰，或先选物品再点击地面放置。重叠摆放会回退至原位。方向键微调选中物品。打开观察手记可以调整大小、切换区域、替换植物或确认移除。替换时可以重新拍照或从图鉴挑选。已有观察保存在原设备，首次打开新版时会按原来的室内或室外位置衔接。

布置菜单提供十三种摆件，包括玻璃生态箱、三层盆栽架、园艺操作台、珐琅浇水壶、庭院茶桌、苔石步道、木栅栏和双层石泉。选中植物或摆件后，沿底部圆环拖动 ⟳ 可连续调整朝向。键盘聚焦旋转手柄后，方向键每次微调 1°，按住 Shift 则每次调整 15°。松手将朝向记入本地草稿，点「保存布置」后生效。室外植株根部会显示与展示尺寸相配的土坑，土沿和松土随雨雪与夜景改变颜色。校园植物园、屋顶露台、中式庭院和繁星之夜共享布置。室外细雨会使叶面湿润，飘雪会在叶片和花瓣上形成积雪。选中摆件可调为 50% 至 200%，选中室内植物可更换赤陶、青瓷或玄武岩盆。点击「花园拍照」，左右拖动环绕，上下拖动调整俯仰。可直接点「平视」或「俯视」，打开「平移」后拖动调整构图，再点「保存照片」导出不含界面控件的 PNG。登录后布局、装饰及场景天气会随账号同步，花友可只读参观。

识别后可在种植工作台阅读物种小科普。精细株形会结合叶序、叶缘、叶宽比例和花序生成，生成期间可先使用基础模型。花友对战的纸面试玩规则见[三回合花展与盆栽扩展方案](docs/play-and-pots.md)。

在布置模式下，拖动、旋转、缩放、换盆和天气切换均在浏览器内预览。切换室内外会保留本次草稿。点「保存布置」后才会同步账号花园；游客保存在当前浏览器。点「取消布置」可放弃本次修改。花架、桌椅按支撑和横板的实际位置检查净空，小株可以放入容得下的空隙。

## 花友互访

在「我的植物园 → 我的花友」输入同学的完整植迹用户名。对方同意后即可参观彼此的三维花园。好友可查看植物和花园布置，照片、发现地点和手记仅主人可见。点好友旁的「赠送分株」可送出一份植物模型，原株会留在自己的花园。对方在「我的花友」中领取并选择室内或室外，也可以婉拒。礼物使用模型肖像，不携带观察原图、地点或手记。申请可以撤回或婉拒，好友可以解除。部署时增加名为 DB 的 D1 绑定，并应用 drizzle 目录下的迁移。

## 从照片到株形

| 环节 | 工作方式 |
| --- | --- |
| 辨认物种 | 浏览器缩放照片后提交给服务端，由 Pl@ntNet 返回至多五个候选。用户确认物种；中文俗名的覆盖情况取决于图鉴与识别数据。 |
| 生成株形 | 服务端将确认后的学名交给模型服务，获取叶形、树冠形态、花瓣数、配色和枝叶比例；展示大小由用户选择。同一浏览器再次收录同种植物时复用缓存。 |
| 绘制花园 | 浏览器将参数转换为低多边形网格并投影到 Canvas。窗台和室外共用色板与明暗规则，支持乔木、灌木、花卉、禾草、莲座和草本六类株形。 |

游客的观察记录保存在当前浏览器，清除站点数据会清空本机花园。在线版右上角可用自选用户名和密码注册植迹账号，注册时需再次输入相同密码。在「我的账号」中可以修改密码。修改后当前浏览器保持登录，其他设备需用新密码重新登录。如果本浏览器仍有旧版平台登录状态，可在「我的账号」里导入旧账号花园。登录后，照片、发现地点、植株配置和观察记录会同步到云端。在「我的账号」中点「导入本机花园」可合并游客记录，发生重叠的物品会移到同区空处。退出后回到游客模式。离线版可种植图鉴示例；实拍识别和 AI 株形生成需要运行在线服务。

## 从源码构建

在仓库根目录使用 Node.js 运行以下命令。构建脚本只使用 Node.js 内置模块，无需安装 npm 依赖。

```sh
node build.mjs campus-flora-offline.html
```

该命令生成可直接打开的 `campus-flora-offline.html`，同时更新在线服务入口 `dist/server/index.js`。仅构建在线版时，运行 `node build.mjs` 即可。

开发者在 Windows 安装 Node.js 与 Go 后，从源码根目录运行 `./offline/package.ps1`。脚本会构建单文件 HTML，将页面嵌入只监听 127.0.0.1 的 Windows 服务，并把启动文件、作品介绍、使用说明与纯离线图鉴一并打包。默认 ZIP 位于源码目录的上一级。运行提交包无需这两套开发工具。

中国大陆的节点选择、账号数据迁移和校园网验收步骤见[国内部署方案](docs/china-hosting.md)。

## 部署在线服务

### Netlify

Netlify 站点使用独立的植迹账号和 PostgreSQL 数据库，首次访问请注册。构建命令为 `node netlify/build.mjs`，静态产物在 `netlify-public/`，同域 `/api/*` 由 Netlify Functions 提供。数据库迁移随部署运行。超过 2 MiB 的花园按段传输，最终保存时检查账号和版本，保留原有的 16 MiB 花园容量。

从仓库安装依赖（`npm ci`），在 Netlify 项目的生产环境中配置 `PLANTNET_API_KEY` 和 `DEEPSEEK_API_KEY`。关联项目后使用 `netlify deploy` 构建预览，再用 `netlify deploy --prod` 发布正式站。

### Worker

将 `dist/server/index.js` 部署到支持 ES Module Worker 和 Web Fetch API 的运行环境。入口导出 `fetch(request, env)`，同时提供首页、照片识别和株形生成接口。植迹账号和花园数据使用名为 `BUCKET` 的 R2 绑定。密码使用随机盐及 PBKDF2-SHA256 派生，会话使用 HTTPS 下的 HttpOnly Cookie，服务端仅存令牌摘要。浏览器设备通过版本校验避免并发覆盖。请在托管平台配置下列运行时变量。

| 配置项 | 用途 |
| --- | --- |
| `PLANTNET_API_KEY` | `POST /api/identify` 接收 JPEG 照片并返回候选物种 |
| `DEEPSEEK_API_KEY` | `POST /api/model` 接收含 `latin` 学名字段的 JSON 并返回株形参数 |

自行部署时，将 [前端配置](dist/app.js) 中的 `hosted` 地址替换为自己的站点，再执行构建。这样离线版的「打开在线版」会指向自己的服务。

## 源码入口

- [页面交互与收藏](dist/app.js) 处理拍照、候选确认、观察记录和株形缓存。
- [植物网格](dist/specimen.js) 与 [花园场景](dist/studio-scene.js) 负责盆栽造型、室外视角与植株点选。
- [识别服务](server/identify.mjs) 与 [建模服务](server/model.mjs) 封装两个外部 API。
- [构建脚本](build.mjs) 将页面、样式和前端脚本打包为单文件演示版与 Worker。
